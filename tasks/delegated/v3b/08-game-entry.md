# Цель
Нельзя выйти в бой с неполной экипировкой; снапшот партии включает доску.

# Контекст
Прочитай: `docs/contracts-collections.md` (п. 1 «Экипировка», 5 «Снапшот»), `backend/app/services/games.py` (`create_game`), `backend/app/services/matchmaking.py` (`enqueue`, `_match_pair`), `backend/app/api/invites.py`.

# Область
`backend/app/services/games.py`, `backend/app/services/matchmaking.py`, `backend/app/api/invites.py`.

# Что сделать
- `games.py::create_game`: перед `loadout_snapshot` — `await ensure_loadout_complete(db, white_id)` и `await ensure_loadout_complete(db, black_id)` (из `app.services.items`). Вызовы `loadout_snapshot(db, white_id, "w")` / `(db, black_id, "b")` не менять (функция сама добавит доску).
- `matchmaking.py::enqueue`: сразу после проверки контроля времени — `await ensure_loadout_complete(db, user.id)`.
- `matchmaking.py::_match_pair`: в `except` добавить ветку для `isinstance(exc, AppError) and exc.code == "LOADOUT_INCOMPLETE"`: в новой сессии `async with SessionLocal() as db2:` проверить `loadout_complete(db2, int(user_id))` для `a` и `b`; неполного — `await redis_client.delete(_user_key(int(user_id)))` (выкинуть из очереди), полного — `await redis_client.lpush(queue_key, user_id)`; затем `return`. Ветку `ALREADY_IN_GAME` и общий случай не менять.
- `api/invites.py`: в `create_invite` после проверки активной партии — `await ensure_loadout_complete(db, user.id)`; в `accept_invite` перед `create_game` — `await ensure_loadout_complete(db, user.id)`.

# Готово, когда
`python3 -m py_compile backend/app/services/games.py backend/app/services/matchmaking.py backend/app/api/invites.py` без ошибок.

# Общие правила
- ЕДИНСТВЕННЫЙ источник истины — `docs/contracts-collections.md` (контракт предметов v3). Имена, поля, коды ошибок, тексты — дословно оттуда.
- Ошибки — только `AppError(status, code, message)` из `app.core.errors`.
- Python 3.12, type hints, async SQLAlchemy 2.0 (`select()`). Время — только `clock.now()` (`import app.core.clock as clock`). Случайность — только `get_rng()` из `app.services.rolls`. Любой `FOR UPDATE` — с `.execution_options(populate_existing=True)`. Баланс — только `economy.apply_delta`.
- Порядок блокировок: `market_listings` → `inventory_items` → `cases` → `games` → `users`.
- Тесты бэкенда в этой волне НЕ запускаются и могут падать — их чинит отдельная волна. Тесты не трогать.
- Менять только файлы из раздела «Область». Не добавлять зависимостей.
- Если что-то не сходится с контрактом или кодом — не придумывать обход, остановиться и описать проблему в SUMMARY.
