# ChessDep

Онлайн-шахматы (PvP) с элементами казино:
- **деп** — в свой ход можно рискнуть фигурой: с шансом `ценность_из / ценность_в` она превращается в более ценную, иначе сгорает (не больше 1 депа за ход и 10 за партию);
- **скины** фигур и досок, выпускаемые коллекциями, **кейсы**, **апгрейд** скинов, **маркет** между игроками, **подарки**.

Валюта ◈ только виртуальная: не покупается и не выводится. Сервер — единственный источник истины: в браузере хранится только cookie сессии, все шансы и броски считаются на сервере.

Подробное ТЗ: [`docs/TZ.md`](docs/TZ.md).

## Требования

- Linux
- Docker и Docker Compose v2

Больше на хосте ничего не нужно: база, Redis и всё остальное поднимаются в контейнерах.

## Запуск

```bash
cp .env.example .env      # поменяйте POSTGRES_PASSWORD (и пароль в DATABASE_URL)
make up                   # сборка и запуск, миграции применяются автоматически
```

Сайт: `http://localhost:8080`.

Первый администратор назначается только из консоли (через сайт роль не выдать):

```bash
make make-admin LOGIN=ваш_логин
```

Остановить: `make down`. Данные (база и Redis) лежат в Docker-томах и переживают перезапуск.

## Что есть на сайте

| Страница | Что там |
|---|---|
| Играть (`/index.html`) | Поиск соперника по контролю времени (3+2, 5+0, 10+0), приглашение друга по ссылке, ежедневный бонус |
| Партия (`/game.html`) | Доска, часы, деп с анимацией для обоих игроков, ничья, сдача, отмена партии |
| Кейсы | Список кейсов, шансы дропа, открытие с лентой |
| Инвентарь | Экипировка по слотам (6 фигур + доска), продажа на маркет, подарок, снятие с продажи |
| Апгрейд | Несколько скинов → один более ценный, с шансом; входы сгорают при любом исходе |
| Маркет | Лоты с фильтрами, покупка, мои лоты, история цен по скину |
| Подарки, Профиль, Лидеры, Коллекции | История подарков; смена пароля, история партий и операций; рейтинг по Elo и балансу; витрина коллекций |
| Админка (`/admin.html`) | Коллекции → скины → кейсы → дропы → выпуск; пользователи (бан, баланс, выдача скина); настройки экономики; маркет; журнал действий |

## Как выпустить новую коллекцию скинов

Админка → «Коллекции»:
1. Создать коллекцию — она появится как черновик, игроки её не видят.
2. Добавить скины: фигура или доска, редкость, ценность, цвет-заглушка.
3. Создать кейс, нажать «Автовеса» (веса по редкости, как в CS) или задать дропы вручную.
4. «Выпустить» — коллекция и кейсы появятся у игроков. После выпуска у скинов можно менять только название, внешний вид, ценность и признак «цель апгрейда».
5. «Снять с выпуска» — кейсы закроются, выпавшие скины останутся у игроков.

Сейчас все скины — белые заглушки (стартовая коллекция Genesis: 22 скина, 2 кейса). Настоящие скины заменят поле `asset` у тех же скинов.

## Настройки экономики

Меняются в админке на вкладке «Настройки», без перезапуска. Среди них: стартовый баланс, ежедневный бонус, награды за партии, множитель шанса депа, комиссия апгрейда и маркета, задержка передачи предметов. Полный список и границы значений — в `docs/TZ.md`, раздел 5.

## Доступ с другой машины

Добавьте адрес, по которому открывают сайт (например `http://192.168.1.10:8080`), в `ALLOWED_ORIGINS` в `.env` через запятую и выполните `make up`. Запросы с других адресов сервер отклоняет (защита от CSRF).

## Устройство

```
backend/    FastAPI + SQLAlchemy + Alembic; app/chess_engine — правила депа поверх python-chess
frontend/   чистые HTML/CSS/JS-модули без сборки
nginx/      статика, прокси API и WebSocket, заголовки безопасности
docs/       ТЗ и аудит старого фронта
tasks/      задания, по которым писался код
legacy/     старый фронт — только как визуальный референс
```

Контейнеры: `nginx` (наружу только он), `api`, `worker` (часы, флаги по времени, матчмейкинг), `migrate`, `postgres`, `redis`.

## Чего пока нет

- **HTTPS.** Сейчас только http. Для выкладки в интернет нужен TLS (сертификаты в nginx) и `COOKIE_SECURE=true` в `.env`. Без этого cookie сессии передаётся открытым текстом.
- **Настоящие скины** — пока белые заглушки.
- **Зрители, чат, бот, полная история ходов в партии** — вне текущего ТЗ.
